# 테스트케이스 초안 (예시 출력)

> `python src/generate_test_cases.py --input examples/sample_requirement.md --platform "Android,iOS,Web"` 실행 시 생성되는 결과물의 예시입니다.

| ID | 제목 | 우선순위 | 플랫폼 | Given | When | Then |
|---|---|---|---|---|---|---|
| TC-01 | 출금액 90% 도달 시 경고 배너 노출 | High | Android/iOS/Web | 사용자의 24시간 누적 출금액이 일일 한도의 89%인 상태 | 추가 출금으로 누적액이 90% 이상이 됨 | 출금 화면 상단에 경고 배너가 남은 한도와 함께 노출된다 |
| TC-02 | 출금 한도 100% 초과 시 버튼 비활성화 | High | Android/iOS/Web | 누적 출금액이 일일 한도의 100%에 도달 | 출금 화면 진입 | 출금 버튼이 비활성화되고 사유 다이얼로그가 노출된다 |
| TC-03 | 자정 기준 누적액 초기화 | Medium | Android/iOS/Web | 전일 누적 출금액이 한도의 95%인 상태로 자정 도래 | 사용자 로컬 타임존 기준 자정 경과 후 화면 새로고침 | 누적 출금액이 0으로 초기화되고 경고 배너가 사라진다 |
| TC-04 | KYC 등급 상향 시 한도 즉시 반영 | High | Android/iOS/Web | Lv.1 사용자가 한도의 95%를 사용해 경고 배너가 노출된 상태 | KYC가 Lv.2로 승인됨 | 새 한도 기준으로 잔여 한도가 재계산되어 배너 상태가 갱신된다 (확인 필요: 승인 반영 지연 시 캐시 처리 방식) |
| TC-05 | 타임존 경계값 - 자정 직전/직후 | Medium | Android/iOS/Web | 자정 1분 전 출금 시도 | 출금 완료 후 1분 경과(자정 통과) | 출금 이력이 정확히 어느 날짜 누적액에 반영되는지 확인 (확인 필요: 서버/클라이언트 타임존 처리 기준) |
| TC-06 | 네트워크 지연 시 배너 상태 불일치 | Low | Android/iOS | 누적 출금액 조회 API 응답 지연 | 사용자가 출금 화면에 빠르게 재진입 | 이전 캐시된 배너 상태가 노출되지 않고 로딩 처리되는지 확인 (확인 필요: 로딩 UX 스펙 부재) |

**요약**: 정상 플로우 3건(TC-01~03), 등급 변경 연동 1건(TC-04), 경계값 1건(TC-05), 에러/지연 케이스 1건(TC-06)으로 구성. "확인 필요" 표시된 3건은 스펙 보완 후 QA 리뷰에서 최종 확정 필요.
